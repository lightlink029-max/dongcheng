## 2. 业务定位与设计原则

### 2.1 当前业务定位

LightLink 第一阶段服务于欧美 B2B 鞋类市场，目标客户包括进口商、批发商和 Private Label 客户。经营角色以“采购/寻源代理”和“中国供应链服务伙伴”为主，不把合作工厂描述成自有工厂。

当前正式运营项目为“欧美鞋类采购与中国供应链运营项目”，首发市场为美国和英国，主要渠道为英文网站、LinkedIn 和 Instagram。后续可以复用同一套项目蓝图扩展到其他国家、品类和经营角色。

### 2.2 一人团队的七条原则

1. **项目驱动。** 所有市场、产品、内容、客户和数据都要能够回到一个运营项目。
2. **Odoo 是唯一业务事实源。** 产品、客户、任务、订单、采购、库存、财务和经营结果以 Odoo 数据为准。
3. **ChatGPT/Codex 是协作入口。** 它负责理解目标、读取事实、制定计划、生成草稿、解释结果和发起受控动作，不另建一套业务账。
4. **先事实、后内容。** 只有经过核实的产品、供应商、价格、认证和交期信息才能进入正式文案；没有依据的内容必须明确标记或删除。
5. **内容按项目和角色规划。** 社媒运营不是“一件商品做一条视频”，而是按行业、经营角色、内容类型、渠道和账号集群持续生产；只有“产品或品类介绍”必须绑定真实产品。
6. **按异常工作。** 日常优先处理逾期、待批准、发布失败、客户待跟进、采购收货和回款异常，不在多个模块之间盲目寻找事项。
7. **用净口径复盘。** 收入、采购成本和毛利必须扣除退款或冲销，避免用毛额误导经营判断。

### 2.3 完整业务闭环

| 阶段 | 主要工作 | 系统结果 | 关键门槛 |
|---|---|---|---|
| 1. 市场项目 | 确定国家、客户类型、角色、目标和渠道 | 市场运营项目、项目蓝图、上线清单 | 定位与客户画像明确 |
| 2. 产品与供应链 | 搜集候选品、核实供应商、MOQ、价格、认证和交期 | 候选产品、产品池、供应商报价 | 产品事实可验证 |
| 3. 内容策略 | 设置内容类型、比例、模板、语言和事实边界 | 内容组合规则、双语模板 | 总占比为 100% |
| 4. 素材生产 | 拍摄、下载、剪辑、字幕、翻译、配音并打标签 | 可复用素材、生产任务、成片 | 素材有授权且标签完整 |
| 5. 账号发布 | 将内容复用到市场、渠道和账号集群 | 渠道内容、发布任务、发布链接 | 真实账号、登录和网络可用 |
| 6. 客户转化 | 接收询盘、建线索、记录需求、跟进、报价 | CRM、客户需求、报价单、销售订单 | 阶段和下一步日期完整 |
| 7. 采购交付 | 下采购单、收货、库存、出库、客户交付 | 采购单、入库、出库、交付状态 | 数量、质量和交期受控 |
| 8. 财务回款 | 客户发票、供应商账单、付款、退款 | 会计凭证和净经营数据 | 退款与冲销已计入 |
| 9. 数据复盘 | 对比流量、询盘、订单、成本、净毛利和内容比例 | 经营快照、优化行动 | 有基线、目标和复盘结论 |

## 3. 软件组成与职责边界

### 3.1 总体结构

| 组成 | 主要职责 | 不负责的事情 |
|---|---|---|
| Odoo 19 | 业务数据、权限、流程、审批、订单、库存、财务、审计 | 不保存外部平台明文密码或浏览器 Cookie |
| LightLink 业务中心 | 一页查看今日事项、业务指标和完整流程入口 | 不替代各业务模块的明细记录 |
| 产品智能中心 | 候选产品采集、评分、审核、产品转化、供应商与图片搜索 | 不把未经核实的网页信息当成正式产品事实 |
| 市场运营中心 | 项目、上线准备、内容策略、素材、账号集群、发布和优化 | 不伪造平台授权或真实发布结果 |
| ChatGPT/Codex + MCP | 读取 Odoo、分析、解释、生成计划与草稿、发起受控写入 | 不成为第二数据库，不绕过 Odoo 权限 |
| Windows 媒体工作站 | 主动领取本地生产任务，下载、剪辑、字幕、翻译、配音、上传成片 | 不要求 Odoo 暴露本地电脑端口 |
| BitBrowser / MuMu / Android 选片器 | 提供真实浏览器环境、人工登录和抖音素材选择 | 不在 Odoo 中保存敏感登录态 |
| Qdrant Cloud | 保存商品图片向量并返回相似产品候选 | 不保存客户上传的原图，不替代商品主数据 |
| 网站与社媒平台 | 展示产品、承接询盘、发布内容和产生渠道数据 | 不作为内部订单与财务事实源 |

### 3.2 受控写入链路

AI 对 Odoo 的写操作遵循：

`读取依据 → 生成行动卡 → 服务端校验 → 展示变更预览 → 用户批准 → 幂等执行 → 状态验证 → 效果复盘`

当前版本所有 AI 写入仍执行预览和批准。为减少一人团队的重复操作，系统已经支持把同一业务目的的多条修改合并为一次批量行动，例如一次更新最多 50 条上线准备项。后续风险分级审批属于规划项，在正式实现前不得假设已自动放行。

以下事项即使以后实行风险分级，也应始终人工确认：

- 对外发布或发送客户消息；
- 确认订单、付款、退款、采购和库存过账；
- 删除正式数据或批量清理；
- 修改账号、密钥、代理、权限或登录环境；
- 重试可能造成重复发布、重复扣款或重复通知的失败任务。

## 5. 市场运营项目

### 5.1 项目是什么

市场运营项目是运营工作的总容器，关联经营赛道、经营角色、产品线、目标市场、发布渠道、账号集群、内容、素材、客户需求和经营数据。相同业务模式可以先维护为“运营项目蓝图”，以后快速复制到新市场或新品类。

### 5.2 新项目建立顺序

1. 选择项目蓝图、经营赛道和主要经营角色。
2. 填写项目目标、目标客户、首发市场和发布渠道。
3. 建立产品池并核实首发产品事实。
4. 初始化上线准备清单、内容类型、建议比例和双语模板。
5. 配置账号集群和发布目的地。
6. 完成硬性门槛并使上线准备达到 100%。
7. 生成渠道内容、审核、创建发布任务并上线。

### 5.3 上线准备清单

上线准备用于回答“还缺什么”和“什么时候可以发布”。每项应包含阶段、负责人、计划完成日期、权重、证据、状态和阻塞原因。硬性门槛缺少证据时，即使总分看起来足够也不能上线。

当前正式鞋类项目共有 28 项上线准备，总权重 100%。截至 2026-09-11，完成度为 0%，有 2 项逾期，因此尚不允许上线。优先完成：

- 英文定位与服务边界；
- 美国和英国的进口商、批发商与 Private Label 客户画像；
- 首批鞋款候选池和真实供应资料；
- 首发内容与素材；
- 真实发布账号和渠道连接。

## 6. 产品智能与供应链事实

### 6.1 产品智能中心的工作流

| 环节 | 操作 | 结果 |
|---|---|---|
| 数据来源 | 配置来源、同步或接收授权推送 | 新候选产品进入系统 |
| 候选产品 | 补充详情、媒体、价格、国家、分类和负责人 | 候选信息可审核 |
| 评分与复核 | 按市场、经营角色和规则评估 | 批准、观察或拒绝建议 |
| 产品转化 | 将合格候选转为 Odoo 产品 | 进入正式产品库和项目产品池 |
| 供应商管理 | 维护供应商、MOQ、报价、产能、交期和合作边界 | 采购与内容使用同一事实 |
| 商品发布 | 补齐网站、销售、采购、库存和图片资料 | 可用于网站、报价和内容 |

### 6.2 产品事实门槛

正式使用前至少核实：

- 产品名称、用途、材质、尺码、颜色和包装；
- 供应商身份、合作关系和是否为自有或合作工厂；
- MOQ、价格区间、打样周期、量产周期和交付条件；
- 认证、测试、商标、图片和款式知识产权；
- 报价有效期、币种、运输与付款边界。

未经核实的信息可以保留在候选区，但不能作为对外确定性承诺。

## 7. 统一社媒内容工作台

### 7.1 为什么要统一

统一社媒内容工作台将原来的“内容计划、内容要求、模板与素材、内容制作与审核、发布任务、账号集群”集中到项目页面。核心目标是先按项目定位、行业和经营角色建立长期内容计划，再将内容复用到不同市场、渠道和账号，而不是机械地为每个商品分别制作一条视频。

### 7.2 十类内容范围

| 内容类型 | 具体要做什么 | 是否必须绑定产品 |
|---|---|---|
| 项目品牌与定位 | 讲清服务谁、解决什么问题、承担什么角色和不承担什么 | 否 |
| 采购代理服务 | 展示需求确认、寻源、筛选、比价、验厂、跟单和验货流程 | 否 |
| 中国供应链能力 | 用产业带、供应商网络、交期和协同实例证明供应能力 | 否 |
| 行业知识 | 解释采购标准、材质、工艺、合规、成本和常见风险 | 否 |
| 供应商、验厂与质检 | 展示供应商筛选、审核、检验项目、缺陷控制和证据 | 否 |
| OEM/ODM 与打样 | 讲需求、设计、材料、样品迭代、确认和量产封样路径 | 否 |
| 包装、验货与交付 | 展示包装规范、装箱、抽检、出货、物流和交付控制 | 否 |
| 产品或品类介绍 | 介绍具体鞋款或品类、用途、规格、MOQ 和差异点 | 是 |
| 客户案例 | 用已授权且可核实的场景说明问题、过程和结果 | 视案例而定 |
| 市场热点 | 将政策、展会、趋势或需求变化转化为买家可执行建议 | 否 |

系统已初始化 4 个经营赛道、9 个主要经营角色和 10 类内容，共 360 套可维护模板。每套模板包括中文制作参考和英文发布参考，模板中的占位内容必须在发布前替换为项目真实事实。

### 7.3 内容比例与视频比例

“建议内容占比”用于规划长期内容结构，“其中视频占比”用于决定该类型有多少内容要做成视频。“查看实际发布占比”用于比较真实结果和目标比例，防止账号长期只发布产品图或只做单一题材。

使用步骤：

1. 按行业和主要经营角色初始化建议比例，确保内容总占比为 100%。
2. 根据当前阶段微调，例如项目初期增加定位、服务和供应链证明，稳定期增加案例、行业知识和热点。
3. 为每个内容类型准备相应图片、视频、工厂、质检、打样、包装或交付素材。
4. 发布后按项目、市场、渠道和账号集群查看实际占比。
5. 结合曝光、点击、询盘、有效客户和订单结果调整下一周期比例。

### 7.4 内容规则与双语模板

项目级内容总规则只填写一次，用于统一目标客户、经营身份、语言、核心卖点、事实边界和行动引导；具体内容类型模板负责告诉制作人员每条内容怎么写、拍什么、展示什么证据。

双语使用方式：

- 中文模板：用于内部理解、拍摄、剪辑和审核；
- 英文模板：用于生成或编写面向目标市场的最终发布内容；
- 英文内容应保持专业 B2B 语气，并根据美国或英国市场调整表达；
- 不翻译或编造未经核实的品牌授权、认证、价格、产能和交期。

### 7.5 素材库

素材库分为两层：Odoo 保存已授权图片、文件、最终成片和本地分镜索引；Windows 工作站保存体积较大的原视频、初剪片段、去字幕版本、配音版本、HeyGen 版本、背景音乐和中间文件。这样原始素材和已处理分镜可以反复使用，Odoo 不会因为上传大量中间视频而膨胀。

本地分镜至少维护：素材名称、经营角色、项目赛道、内容场景、分镜用途、画面类型、语言、时长、画幅、字幕状态、统一音色版本、版权状态和本地文件标识。Odoo 只保存这些索引信息，不保存本地绝对路径，也不能直接删除本地文件。

推荐标签包括：产品、工厂、设备、工艺、验厂、质检、缺陷、打样、包装、装箱、仓库、交付、人物出镜、英文口播、竖屏、横屏、已授权、待复核等。素材标签是后续统计“什么类型的素材在什么账号中占比多少”的基础。

## 8. 内容制作、账号集群与发布

### 8.1 内容任务状态

内容从草稿开始，经过 AI 生成或人工编辑、事实核对、审核、待发布、发布中、已发布或失败。渠道内容可以生成图片或视频素材，也可以创建 Odoo 社媒帖子；真实外部发布结果必须保存发布链接和时间。

### 8.2 账号集群

账号集群把一组面向相同市场、语言、业务定位或内容策略的账号组织在一起。内容先属于项目，再按目标市场、渠道和账号集群复用。账号集群中应维护平台、账号名称、用途、语言、市场、状态和发布边界，不在 Odoo 中记录密码和 Cookie。

### 8.3 本地媒体生产

视频制作采用“先方案、再分镜、最后合成”，不能让 AI 跳过故事板直接随机拼接：

1. 在 Odoo 渠道内容中确认整条视频的目标客户、核心观点、时长、叙事顺序和行动引导。
2. 添加分镜需求，逐条写明画面要求、叙事作用、对应文案、目标时长和是否必要，然后锁定故事板。
3. Windows 工作站领取任务，优先从本地分镜素材库选择；缺少的分镜再从抖音链接、剪贴板链接或本地自拍视频生产。
4. 每条素材独立完成初剪和人工分类，逐条决定是否清理硬字幕；只有口播人脸片段进入 HeyGen，其余片段跳过口型同步。
5. 项目统一目标语言和音色。处理完成的片段自动进入本地素材库，并关联当前经营角色、赛道、场景和分镜用途。
6. 人工选择每个分镜的最终片段并确定顺序。必要分镜缺失、分镜重复、片段未处理或音色不一致时，系统阻止合成。
7. 最终步骤只执行片段拼接、统一英文字幕、背景音乐和导出，不重复翻译、去字幕或口型处理。
8. 预览确认后，只把最终成片、字幕和成片使用清单回传 Odoo；原片、分镜和中间版本继续保留在本机。

Windows 媒体工作站复用以下处理能力：

- 下载已授权的素材；
- 图片排版和视频基础剪辑；
- 字幕识别、翻译和烧录；
- 本地或云端语音合成；
- 音乐混合、比例裁切和版本管理；
- 预览确认后把最终成片上传回 Odoo。

本地 V2 使用独立的 `media-library-v2.db`，不兼容导入旧项目数据库。首次安装时旧 `selections.db` 只会复制到归档目录，不会迁移旧记录，也不会删除或覆盖原视频。

本地工作站采用租约机制；电脑崩溃或离线后，任务会在租约过期后重新进入队列。抖音图片搜索和选片涉及登录、验证码和实际素材选择时，由用户在 MuMu/抖音完成，Android 选片器把选中的链接交给本地工作站。

### 8.4 发布安全

- 没有平台名称、账号名称和真实登录授权时，只能写测试数据和验证任务链路，不能声称真实发布成功。
- 平台拒绝授权、账号失效、验证码、人机验证和永久性参数错误不自动重试。
- 只有明确属于临时网络或限流问题的任务才允许安全重试。
- 同一发布动作使用幂等键，避免重复帖子或重复通知。

## 9. CRM、销售、采购、库存与交付

### 9.1 客户关系与需求

新询盘进入 CRM 后，应完成联系人、来源渠道、所属项目、目标产品、数量、国家、预算、目标采购日期、下一步动作和下一次跟进日期。赢单时，关联客户需求的阶段应同步，避免 CRM 已赢单而需求仍停留在“new”。

一人团队每天只需要优先处理：今天到期、已逾期、高价值、长期未响应和缺少下一步日期的线索。

### 9.2 报价与销售订单

报价单确认后成为销售订单，但仍应计入“报价/漏斗”统计，确保漏斗没有因为状态转换而少算。订单必须保留项目、客户、来源渠道和内容归因，方便计算哪个渠道、内容类型和账号带来订单。

### 9.3 采购与库存

销售需求转采购时，维护供应商、采购数量、成本、交期和关联项目。采购确认后完成收货，销售侧完成出库和交付。异常数量、质检失败、延期、退货或重新交付必须记录在对应单据上，而不是只写在聊天记录中。

## 10. 财务与经营数据

### 10.1 经营数据入口

“经营数据”可从 LightLink 业务中心的“财务与复盘”进入，也作为仪表板中的 LightLink 菜单显示。经营数据按日期、项目、发布目标、平台账号和内容聚合曝光、播放/浏览、点击、询盘、有效客户、报价、订单、销售额、采购成本和流量成本。

### 10.2 净口径

当前已实现并验证以下口径：

| 指标 | 计算原则 |
|---|---|
| 开票收入 | 已确认客户发票金额 |
| 客户退款 | 已确认退款或贷项金额 |
| 净收入 | 开票收入减客户退款 |
| 供应商账单 | 已确认供应商账单金额 |
| 供应商退款 | 已确认供应商退款金额 |
| 净采购成本 | 供应商账单减供应商退款 |
| 净毛利 | 净收入减净采购成本及已纳入的相关成本 |

测试基线中，2 张销售订单合计 4,000 USD；客户发票 2,000 USD、客户退款 2,000 USD；供应商账单 1,200 USD、供应商退款 1,200 USD，因此净收入、净采购成本和净毛利均为 0。此结果用于证明退款后不会继续显示虚假的正收入或毛利。

### 10.3 复盘方式

每周查看：流量到询盘转化、有效客户率、报价率、订单率、内容类型实际占比、视频占比和发布异常。每月查看：净收入、净成本、净毛利、渠道获客成本、产品线贡献和退货退款原因。

优化行动必须记录基线、目标、拟执行动作、观察天数、成功标准、回滚标准、实际结果和最终结论。

## 11. 网站以图搜索产品

### 11.1 功能说明

网站访客可以上传 JPG、PNG 或 WebP 产品参考图片，系统提取图片视觉特征并在 Qdrant 中搜索相似商品，只返回允许在网站销售且已建立图片索引的产品。客户原图只用于本次特征提取，不公开保存原图。

### 11.2 当前实现状态

- Qdrant Cloud 免费集群已经连接；
- 商品图片索引和网站上传入口已上线；
- 当前使用轻量 Pillow 视觉向量，维度为 512；
- 已支持原始图片数据、Base64 数据和 WebP；
- 已建立 Qdrant payload 索引并启用自适应相关度过滤；
- 同图搜索已经验证只返回自身商品。

当前模型适合小规模商品库的近似检索，但不是完整 CLIP 多模态模型。对于外观接近但类别不同的商品，系统会通过阈值和候选差距过滤低相关结果；如果没有可靠结果，应显示“没有找到足够相似的产品”，不能为了填满数量而展示无关商品。

### 11.3 管理操作

1. 产品发布前确认主图是可识别的 JPG、PNG 或 WebP。
2. 在产品“图片搜索”页点击“立即更新图片索引”。
3. 确认索引状态为已完成，错误字段为空。
4. 在网站上传同图、相似图和无关图分别测试。
5. 商品图片、公开状态或销售状态变化后重新索引。

免费集群足以支持当前约 1,000～5,000 个产品、每个 3 张图片和每天几十到几百次搜索。容量、内存、延迟或请求量接近集群限制时，再评估付费扩容或切换更强的 CLIP 服务。

## 16. 常见问题与排查

### 16.1 模块升级后页面没变化

1. 确认 Odoo.sh 最新构建成功并且模块版本已经升级。
2. 在 Odoo 中升级对应模块，而不是只刷新网页。
3. 强制刷新浏览器或清理当前站点缓存。
4. 重新打开目标记录，确认不是旧标签页缓存。
5. 如果显示“加载模块时至少有一项测试失败”，先查看构建日志中的第一条真实断言或 traceback，不要只重复升级。

### 16.2 页面被挤出或出现横向滚动

确认是否打开了右侧消息栏、浏览器缩放是否过大、表格是否包含过多可见列。优先收起消息栏、恢复 100% 缩放并隐藏低频列。若仍异常，应修复视图的响应式布局，不能依赖用户长期横向滚动。

### 16.3 本地任务不执行

检查 Windows 节点在线状态、任务是否为 queued、租约是否过期、本地日志和 Odoo 地址是否正确。账号登录、验证码或应用界面变化属于用户交互问题，不应无限自动重试。

### 16.4 图片搜索返回无关产品

先确认所有候选商品已重新索引，再用同图、同类图和无关图测试。如果低分结果仍被显示，应提高最低阈值或扩大第一名与后续候选的差距要求。结果不足时少显示或不显示，不能强制凑满 12 个商品。
