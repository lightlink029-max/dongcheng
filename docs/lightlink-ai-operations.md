# LightLink AI 外贸运营驾驶舱

## 产品边界

LightLink AI 是 Odoo 的对话式运营入口，不是第二套业务系统。Odoo 保存产品事实、权限、客户、任务、订单、经营指标和全部执行状态；ChatGPT负责理解目标、读取必要数据、解释依据、生成方案和内容，并在用户批准后调用受控行动。

任何写操作都走同一条链路：

`读取依据 → 生成行动卡 → 服务端规则校验 → 展示预览 → 人工确认 → 幂等执行 → 状态验证 → 效果复盘`

## 集中功能模块

| 模块 | ChatGPT负责 | Odoo负责 | 人必须参与 |
|---|---|---|---|
| 每日驾驶舱 | 解释阻塞、排序机会、提出下一步 | 聚合项目、产品、发布、账号、客户和审批数据 | 决定优先级冲突与资源分配 |
| 产品上市 | 根据已核实事实分析市场适配和资料缺口 | 保存属性、价格、MOQ、交期、合规与硬门槛 | 确认证书、参数、供应与宣传边界 |
| 内容生产 | 生成分市场、语言和渠道的标题、正文、SEO、视频脚本与素材要求 | 硬门槛校验、草稿版本、审核状态和发布任务 | 审核事实、品牌语气与最终发布版本 |
| 发布异常 | 解释失败并区分临时错误和高风险错误 | Worker状态、环境校验、队列、重试与审计 | 处理登录、账号风险、页面变化和违规问题 |
| 客户跟进 | 排序客户、生成回复草稿和跟进计划 | CRM活动、负责人、阶段、来源与销售归因 | 确认报价、承诺、邮件内容和发送 |
| 经营优化 | 对比漏斗，生成有基线、目标、周期和回退条件的实验 | 每日指标快照、实验状态和最终效果 | 批准实验并决定采纳、迭代或回退 |

## 快速复制新项目

新增西非医疗、南美日用品、非洲储能等项目时，不复制代码和菜单。管理员维护少量版本化蓝图，运营人员只选择蓝图、产品线、首批产品、市场和渠道。系统自动建立项目产品池和内容骨架，后续差异保存在项目数据中。

蓝图只定义稳定结构：赛道、经营角色、能力、默认目标、客户画像、合规提醒、KPI和内容栏目。国家法规、产品证书、价格与库存必须继续来自正式业务记录，不能写死在提示词中。

## 安全和可维护性

- API按照当前Odoo API用户运行，并继续受访问权限和多公司规则约束。
- MCP只暴露14个业务工具，不开放通用数据库增删改。
- 写操作使用30分钟签名令牌、目标记录版本快照和公司级幂等键。
- 预览后目标记录发生变化时必须重新生成预览。
- 账号密码、Worker Token、渠道凭据和固定IP不返回给模型。
- 只有网络、超时和明确临时错误允许批准重试；登录、权限、合规和环境错误转人工任务。
- AI运行、行动、执行和反馈分层记录，长对话不是业务状态来源。

两人维护建议：一人负责Odoo模型、权限、规则和数据质量；一人负责MCP工具、提示说明、驾驶舱和验收用例。新增业务优先配置蓝图和赛道数据，只有出现新的业务动作或事实模型时才改代码。

## 分期上线

1. 测试分支：升级Odoo模块，配置只读API用户，验证驾驶舱和全部读取工具。
2. 小范围写回：开放项目任务、CRM活动、内容草稿和安全重试；逐项验证预览、权限、过期令牌、重复提交和目标变化。
3. 经营闭环：启用每日快照、周复盘、优化实验和反馈记录，以有效询盘、响应时效、发布成功率、转化率和毛利为结果指标。
4. 正式推广：为不同岗位配置最小Odoo权限，接入公开HTTPS MCP时使用OAuth 2.1，并保留本地插件作为开发与应急入口。

## 发布验收

- 所有AI结论能回溯到Odoo记录。
- 未经明确确认不能修改业务数据。
- 同一幂等键重复提交不会重复创建记录。
- 预览后业务记录变化会阻止执行。
- 不合规或资料不完整的产品不能生成对外内容。
- 高风险发布错误不能被AI自动重试。
- 从询盘到报价、订单、收入和优化实验能够按项目、市场、渠道追踪。
