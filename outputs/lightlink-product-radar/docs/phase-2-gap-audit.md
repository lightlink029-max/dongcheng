# 第二阶段：自动监控与机会初筛——功能差距自查

更新时间：2026-09-19

结论：当前系统已经具备第二阶段的本地骨架和隔离灰度测试能力，但尚未达到完整验收标准。不能把“来源卡片存在”或“可人工导入”视为“真实连接器已稳定运行”。

## 逐项核对

| 功能 | 状态 | 已实现 | 仍缺失 |
|---|---|---|---|
| 1. 数据源连接中心 | 部分完成 | 统一入口、加密凭证、API/公开数据/导出/上传说明、固定平台目录 | 来源级覆盖国家、更新频率、配额、最近成功时间、标准健康状态；多数来源尚无真实连接器 |
| 2. 监控执行引擎 | 部分完成 | 1/3/7/14/30天频率、立即执行、只执行到期规则、本机调度器、运行历史 | 标准失败分类、耗时、自动重试一次、认证错误禁止重试、连续失败策略 |
| 3. 统一信号入库 | 已完成 | 七类信号、地区/画像/产品/期间/来源/等级/有效期字段及导入校验 | 各连接器仍需按统一协议真正产出信号 |
| 4. 信号去重与复用 | 部分完成 | 唯一指纹、跨监控引用、版本追加、不覆盖旧证据 | 过期自动标记“需复核”、项目复用关系可视化 |
| 5. 事件日历 | 部分完成 | 事件类型、开始/结束时间、采购提前期、最晚交付、来源和归档 | 独立预热期/采购窗口字段、事件模板、窗口关闭提醒 |
| 6. 趋势与异常识别 | 未完成 | 旧产品雷达有部分评分逻辑 | 情报信号的同比、环比、连续增长、季节性、单位价值、异常值和至少两期门槛 |
| 7. 机会候选生成 | 部分完成 | 两来源、两证据类型、至少一类需求证据的过闸；不会自动建项目 | 推荐画像、场景、渠道、最多5个产品家族、冲突项、复查日期 |
| 8. 机会类型判断 | 部分完成 | 蓝海候选、增长红海、短期、长期、观察 | 季节性、风险替代、明确阻断/建议Pass；完整依据展开页 |
| 9. 人工审核工作台 | 部分完成 | 接受、继续观察、Pass及原因 | 调整范围、设置复核日期、合并候选、从候选回到全球画像并人工创建项目 |
| 10. 待办与通知 | 部分完成 | 候选、等待数据、运行失败待办 | 授权失效、窗口关闭、证据过期/冲突、连续失败、到期复核以及同类通知合并 |

## 验收标准核对

| 验收标准 | 结果 |
|---|---|
| 到期监控自动执行并保留历史 | 通过 |
| 至少3类真实来源稳定产生统一信号 | 未通过；当前主要依赖本地贸易缓存、事件和人工/授权导入 |
| 多监控不重复保存相同证据 | 通过 |
| 信号生成待审核机会且不自动建项目 | 通过 |
| 标签可追溯到原始来源和计算依据 | 部分通过；后端保留信号引用，前端缺完整展开页 |
| 权限失败、空值、确认零严格区分 | 部分通过；旧雷达区分完整，情报连接器层尚未建立统一错误模型 |
| 失败不产生虚假低分 | 通过 |
| 两人团队只处理异常、候选和复核 | 部分通过；待办存在，通知合并和复核到期仍缺失 |

## 下一步开发顺序

1. 建立统一连接器协议和来源健康模型：覆盖、配额、最后成功、耗时、错误分类和一次性重试。
2. 先让 UN Comtrade、Eurostat、HMRC 三个官方来源真实产出统一信号，再接 Google Trends 和 Odoo 只读结果。
3. 增加时间序列、至少两期门槛、同比/环比/季节性、异常检测和证据过期状态。
4. 补齐候选画像、渠道、场景、最多5个产品家族推荐及季节性/风险替代标签。
5. 补齐调整、复核日期、合并和从全球画像人工建项目的审核动作。
6. 最后增加去重通知与每日两人工作队列。

## 灰度测试边界

- 每条非归档监控都可选择“达到候选门槛、只有热度信号、来源等待数据、来源执行失败”四种场景。
- 灰度测试复用正式证据闸门和执行步骤，但只写入标记为 `simulation` 的运行记录。
- 灰度数据不写入正式信号、候选、评分或验证项目，也不改变监控的下次执行时间。
- 正式统计、失败待办和等待数据待办排除灰度运行。

## 推荐的人机协作方式

新增“AI 协作工作台”，复用现有本机 Codex 任务通道，不要求用户在聊天窗口重复描述上下文。

### 页面入口

- 每条监控提供“交给 AI”菜单：补官方贸易数据、检查 HS/CN 口径、解释异常、补证据缺口、生成候选摘要。
- 每个候选提供：复核证据冲突、建议画像/矩阵、准备人工决策摘要。
- 情报首页提供“今日工作队列”：只显示授权、异常、候选和到期复核。

### 结构化交互

系统自动带入监控、地区、画像、产品家族、关键词、已有来源、缺口和运行历史。用户只需填写：

1. 本次目标；
2. 时间范围；
3. 允许使用的数据来源；
4. 是否只预览；
5. 需要人工确认的业务口径。

### 任务状态

`草稿 → 等待执行 → AI处理中 → 待你确认 → 已写回 / 已驳回 / 失败`

- AI 结果先进入预览，用户确认后才写入正式信号或调整监控。
- 涉及授权、HS口径、合并、Pass和创建项目必须人工确认。
- 每条结果保留任务输入、来源、变更差异、确认人和写回时间。

### 实施建议

在真实连接器和趋势计算完成后开发该工作台。技术上增加 `intelligence_monitor` 独立任务通道和结构化请求/结果表，避免把自由聊天文本当作业务状态。
