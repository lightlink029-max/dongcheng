# LightLink 外贸情报站：长期产品设计与实施基线

## 1. 产品定位

LightLink 不再是一次性“找爆款”工具，而是面向两人外贸团队的长期情报与验证系统。系统持续回答四个问题：

1. 哪个地区正在出现采购触发条件；
2. 哪类买家、什么销售场景和哪些产品矩阵可能匹配；
3. 真实需求、竞争、供应、利润与合规是否支持投入；
4. 第一轮真实反馈是否足以进入下一轮，否则何时 Pass、暂停或重新触发。

系统只记录证据、假设、行动和结果，不把缺失值当成 0，不在真实客户和履约数据出现前虚构“客户价值”或“供应商能力”。

## 2. 核心闭环

```text
触发事件/持续采购信号
        ↓
地区市场规模、增速、季节性、竞争与进口来源
        ↓
目标买家画像 × 采购场景 × 销售渠道
        ↓
关联产品矩阵 → 第一批候选产品家族（默认最多 5，可配置）
        ↓
第一轮：公开证据 + 首批客户开发 + 同规格供应询价 + 初步合规/利润
        ↓
继续 / 调整 / 补证据 / 暂停 / Pass
        ↓
第二轮：用真实回复、RFQ、样品、报价和拒绝原因修正画像与产品方案
        ↓
第三轮：样品/试单/首单履约 → 常态开发与复购监控
```

任何阶段都允许回到“信号监控”，但不覆盖历史轮次。新证据追加到时间线，旧结论保留当时的版本和依据。

## 3. 信息架构

### 3.1 情报总览

- 今日必须处理：到期复核、数据源失败、客户待跟进、供应报价超期；
- 新增信号：事件、注意力、B2B采购、进口贸易、法规、内部业务；
- 机会漏斗：观察 → 候选 → 第一轮 → 第二轮 → 样品/试单 → 常态开发；
- 两人分工：客户负责人、供应负责人；
- 只显示基于真实记录的数字，不放演示 KPI。

### 3.2 产品机会雷达

- 目标地区使用可维护主数据，支持配置 19 个及以上市场；当前以 14 个业务区域组加“全球”运行，待最终市场清单确定后无需改代码即可扩展；
- 建立监控规则，而不是直接建立验证项目；
- 把触发事件与产品、地区、画像和渠道形成可追踪候选；
- 展示注意力、采购意向、贸易事实、竞争供给、法规和内部结果六类信号；
- 达到进入门槛后，才从全球画像创建验证项目。

### 3.3 全球买家画像

- 画像分类、价值链角色、采购场景、销售渠道、关注点、采购触发和订单特征；
- 画像 × 地区 × 产品矩阵关系；
- 画像主数据与具体买家公司分离；
- 画像关系只生成候选，不直接生成客户价值高分。

### 3.4 验证项目与轮次

- 项目只能从全球画像和矩阵关系发起；
- 一个项目可选多个有关联的产品矩阵，默认上限 5，项目可单独配置；
- 相同画像、地区、场景和渠道只能有一个活动项目；
- 每轮对产品家族分别做继续、调整或 Pass；
- 第一轮完成价值发现，第二轮完成商业验证，第三轮验证首单履约；
- 项目和轮次支持搜索、分页、状态/阶段/地区/画像/负责人/复核日期筛选。

### 3.5 资产库

- 产品家族主数据；
- 产品规格/商业变体；
- 地区 × 产品家族共享档案；
- 买家公司与联系人；
- 供应商、工厂、生产地和报价；
- 证据库及证据引用；
- 合规、认证、物流与关税清单。

同一产品家族在不同中国产区、工厂、材料、质量、MOQ、价格、交期或贸易条款下，必须保存为独立“供应方案/报价版本”，不能覆盖产品家族主数据，也不能把一家工厂的结果推断为整个产品家族能力。

### 3.6 任务中心与数据来源

- 任务中心只呈现正在执行、失败、待人工和已完成任务；
- 数据来源维护连接状态、授权方式、覆盖地区、更新频率、配额、失败原因和最后成功时间；
- 不为登录失败、验证码、权限不足或限流提供绕过方案；
- 未授权平台采用官方导出或人工上传，不以不稳定爬虫作为核心依赖。

## 4. 市场信号分层

| 信号层 | 典型来源 | 用途 | 禁止推断 |
| --- | --- | --- | --- |
| 事件与时机 | 节日、赛事、天气、战争、法规、招标、设备周期 | 判断为什么现在可能触发采购 | 单个事件不等于确定需求 |
| 注意力 | Google Trends、Keyword Planner、TikTok、YouTube、电商热榜 | 发现关注度、关键词和内容变化 | 关注度不等于采购量 |
| B2B采购与供给 | Alibaba.com、中国制造网、Global Sources、行业平台 | RFQ、供给密度、价格带、MOQ、交期和认证 | 商品数不等于需求规模；页面价不等于成交价 |
| 贸易事实 | UN Comtrade、Eurostat、各国海关/统计局 | 进口规模、增速、季节性、伙伴结构、单位价值代理 | 进口额不等于终端销售额 |
| 竞争与渠道 | Amazon、eBay、Walmart、区域平台、买家目录 | 渠道价格、产品结构、评价和竞争密度 | 页面样本不代表全市场 |
| 内部业务 | Odoo CRM、RFQ、采购、销售、发票、复购 | 验证真实客户、利润、履约和复购 | 少量个案不自动代表整个市场 |

### 4.1 触发事件目录

触发事件使用可维护目录，不写死为几个按钮：

- 周期：换季、返校季、节假日、促销季、旅游季、预算周期、日常补货；
- 赛事与文化：世界杯、奥运会、区域赛事、展会、音乐节、婚庆和节庆；
- 宏观与风险：战争、制裁、关税、汇率、运价、原材料价格、港口/供应中断；
- 天气与公共事件：极端高温/低温、洪水、台风、火灾、地震、疫情和公共卫生；
- 法规：禁限用物质、认证、标签、能效、包装、生产者责任和海关规则变化；
- 产业：设备更新、技术升级、新品发布、召回、产能迁移、基建和门店扩张；
- 采购行为：公开招标、RFQ、补货频率变化、库存不足、大客户目录变化；
- 注意力：短视频爆款、搜索词突增、跨境平台热卖和评价异常增长。

每条监控规则至少保存：地区、事件类型、名称、关键词、可选画像、可选产品家族、检查频率、信号类型、状态、上次/下次执行时间。

## 5. 数据来源与接入顺序

### P0：稳定官方数据与内部数据

- UN Comtrade 作为全球统一兜底；
- Eurostat Comext、英国 HMRC、美国 USITC/Census、加拿大统计局、日本海关、澳大利亚 ABS、中国海关等国家来源作为重点市场优先来源；
- Odoo CRM、报价、订单和复购作为最终业务验证。

### P1：B2B平台

- Alibaba.com、中国制造网、Global Sources；
- 采集产品/供应商数量、产区、公开价格区间、MOQ、交期、认证、审核状态和可用 RFQ；
- 自动化必须基于官方接口、账户授权或官方导出；没有稳定权限时使用文件导入和公开页有限抽样。

### P2：注意力和零售渠道

- Google Trends / Keyword Planner；
- TikTok、YouTube、Meta；
- Amazon、eBay、Walmart、区域电商平台；
- 只作为发现和交叉验证，不单独触发采购决策。

## 6. 数据模型与去重

### 6.1 市场信号

`market_signals` 保存统一事实：

- `signal_type`：event、attention、b2b_demand、supply_competition、official_trade、regulation、internal；
- 地区、画像、产品家族、HS/CN 编码、期间；
- 指标、值、单位、方向、置信度和证据等级；
- 来源 ID、原始链接、采集时间、过期时间、状态和缺失原因；
- 原始数据只追加，修正通过新版本完成。

唯一指纹由“来源 + 地区 + 产品/HS + 信号类型 + 指标 + 期间 + 原记录标识”构成。多个项目通过引用表复用同一条信号，不能复制证据。

### 6.2 项目去重

活动项目唯一键：

`画像 + 地区 + 采购场景 + 销售渠道`

创建时如命中已有活动项目，系统必须提供：进入原项目、把新矩阵加入当前轮次；不得悄悄建立重复项目。

### 6.3 产品与供应去重

- 产品家族是稳定的商业分类；
- 商业变体保存规格、用途、包装和目标渠道；
- 供应方案保存工厂、产区、材料、质量等级、MOQ、价格、交期、产能、贸易条款、证书版本和有效期；
- 报价指纹使用“供应商 + 规格版本 + 贸易条款 + 币种 + 有效期”；
- 产品家族 Pass 不删除共享档案和历史报价。

## 7. 评分与决策

### 7.1 评分出现条件

- 市场机会：至少有一条官方贸易/明确买家需求证据，再加一条独立来源；
- 客户价值：只有真实买家公司、有效回复、RFQ、样品或成交出现后评分；
- 供应可行：至少有同规格报价和供应商核验后评分；
- 履约能力：只有样品、试单或真实订单完成后评分；
- 未知显示“待验证”，不能显示 0 分或默认高分。

### 7.2 机会标签

- 蓝海候选：需求持续增长、合格竞争供给相对有限、进入门槛可完成；
- 增长红海：需求增长但竞争和获客成本较高；
- 短期机会：事件窗口明确，采购周期与交付周期能赶上；
- 长期机会：多年度增长、复购逻辑明确且不依赖单一事件；
- 观察：信号冲突或证据不足；
- Pass：需求、利润、合规、交付或客户反馈中存在明确阻断。

### 7.3 第一轮最低完成标准

1. 明确目标地区、画像、场景、渠道和最多 5 个有关联产品家族；
2. 至少一条官方需求/贸易证据和一条独立渠道/买家证据；
3. 建立第一批目标客户名单并记录实际联系结果；
4. 对保留的产品家族取得同规格、同贸易条款的初步供应报价；
5. 完成粗略利润、物流和强制合规检查；
6. 为每个产品家族选择继续、调整或 Pass，并记录下一轮目标与复核日期。

不能强制要求所有家族同时填满固定数量的客户和供应商；系统应显示证据差距和投入优先级，由两人团队先排除明显不成立的候选。

## 8. 两人团队责任

### ChatGPT/Codex 自动完成

- 检查本地缓存和全局证据库；
- 选择合适的官方来源并建议 HS/CN 编码；
- 采集公开或已授权数据、统一口径、去重、计算同比/环比/季节性；
- 从信号生成画像和产品矩阵候选；
- 汇总客户反馈、供应报价、证据冲突和缺口；
- 生成下一步建议，但不自动推进阶段。

### 用户完成

- 提供平台授权、官方导出和 Odoo 最小权限；
- 确认产品业务口径和多 HS 编码选择；
- 联系真实买家、询价供应商、推进样品和试单；
- 核验工厂、质量、证书原件、合同、现金周期和最终利润；
- 确认继续、调整、暂停、Pass 和正式投入。

### 共同完成

- 定义第一轮范围与成功/停止条件；
- 处理矛盾证据和异常数据；
- 复盘真实反馈并修改画像、产品矩阵和报价策略；
- 决定是否进入下一轮。

## 9. 生命周期、作废与删除

- 项目状态：`active → review_due → scaling / hold / passed / voided`；
- 轮次状态：`active → decided / stopped`；
- 监控状态：`active → paused / archived`；
- 作废必须选择原因并填写说明；重复/合并时指向替代项目；
- 作废终止活动轮次和待执行任务，但不删除证据、客户反馈和共享产品档案；
- Pass 表示当前假设不值得继续投入，不表示删除产品家族；
- 物理删除仅用于明确识别的测试数据和法律/隐私删除请求；
- 清理历史测试数据时保留：系统分类、产品主数据、画像模板、来源配置和加密凭证。

## 10. 交互和可访问性

- 详情使用可关闭的 Sheet；标题区同时提供“返回项目”文字按钮和关闭按钮；
- 浏览器返回键应关闭当前详情或返回上一页，不得陷入下一层；
- “查看证据”进入详情后保留来源轮次和家族上下文；
- 无实际动作的卡片不得做成按钮；
- 删除、作废、Pass、强制刷新均需确认并说明影响；
- 所有分页、筛选和当前详情状态进入 URL，以便刷新和返回；
- 移动端保留核心模块，次要筛选放入筛选面板。

## 11. 长期维护要求

- 信号、来源、触发器、评分和状态均由共享常量定义，前后端不能各写一套；
- 数据源连接器遵循统一接口，记录覆盖、速率、授权、最后成功和失败原因；
- 评分公式带版本，历史快照不重算覆盖；
- 所有外部记录保留原始链接、时间、地区、口径和来源等级；
- 写入操作幂等，AI/Odoo/用户都通过同一服务层，不直接改数据库；
- 新功能至少包含类型校验、业务单元测试、接口测试和关键交互验证；
- 默认本地优先，未来上线时增加登录、公司隔离、审计和备份，不改变业务模型。

## 12. 分阶段实施

### 第一阶段：情报站骨架

- 新增情报总览、统一信号分层、触发器目录和监控规则；
- 改造导航和品牌，隐藏旧的平行调研入口；
- 数据来源加入 Alibaba.com、中国制造网及重点国家官方进口数据；
- 清理现有扫描、调研和验证测试记录，保留主数据与凭证；
- 保留现有全球画像、验证项目、证据复用、分页和作废能力。

### 第二阶段：自动监控

- 为已授权来源建立连接器与定时采集；
- 建立事件日历、异常检测、跨来源关联和通知；
- 将合格信号转成待审核的画像/矩阵候选，不自动创建项目。

当前已实现第二阶段的本地可用闭环：统一来源主目录、每 5 分钟到期检查、单条/批量执行、事件日历、本地贸易证据复用、授权证据导入、跨监控去重、不可变版本记录、跨来源候选门槛、人工接受/观察/Pass 和运行历史。未配置授权的外部来源只进入“等待授权/导入”，不会产生伪造数据。各平台官网连接器与生产告警按来源逐个接入，不能用通用爬虫替代授权。

第二阶段机会候选最低门槛：

- 至少 2 个独立可靠来源；
- 至少 2 类证据；
- 至少 1 类属于官方贸易、B2B 采购或内部经营结果；
- `official / primary / internal` 且置信度不低于 40 的有效数据才参与过闸；
- 只有事件或注意力时继续观察，不生成机会候选；
- 蓝海、红海、短期、长期均为待验证分类，不能替代买家回复、报价、样品和履约。

### 第三阶段：真实业务闭环

- Odoo CRM、采购、销售、发票和复购同步；
- 供应方案、统一 RFQ、样品和履约记录；
- 用真实回复和成交校准评分、停止条件和资源分配。

## 13. 第一阶段验收标准

- 默认首页和品牌显示“LightLink 外贸情报站”；
- 能创建、查看、筛选和归档地区触发监控；
- 市场信号明确分层，平台供给不再等同注意力或真实需求；
- 来源页能看到阿里国际站、中国制造网、UN Comtrade 和重点国家官方贸易来源及接入边界；
- 验证项目仍只能从全球画像发起，默认产品家族上限为 5 且可配置；
- 测试扫描、旧调研项目、测试验证项目和测试证据被清理；
- 系统分类、产品家族、画像模板、矩阵种子和已配置凭证保持不变；
- 类型检查、Lint、业务测试和生产构建全部通过。
