# LightLink 外贸情报站

面向两人外贸团队的本地优先情报与验证工作台。系统先监控目标地区的采购触发事件、注意力、B2B 需求、供应竞争、官方贸易、法规和内部经营信号，再把候选机会连接到全球买家画像、产品矩阵、验证项目与真实客户反馈。

系统不会把浏览量当采购量，不会把阿里国际站、中国制造网等平台挂牌当成交，也不会在缺少真实回复、报价、样品或订单时提前给出客户价值和供应商能力分。当前产品闭环和长期数据模型见 [`docs/foreign-trade-intelligence-station-design.md`](docs/foreign-trade-intelligence-station-design.md)。

## 最快启动（Windows）

双击 `start-radar.cmd`。脚本会检查 Node.js、依赖、构建产物和本地数据库，然后打开：

`http://127.0.0.1:8787`

首次启动需要 Node.js 22.13 或更高版本。关闭启动窗口即可停止软件。

开发模式：

```powershell
npm run dev
```

完整验证：

```powershell
npm run verify
```

## 在另一台电脑安装

项目保存在 GitHub 仓库的 `outputs/lightlink-product-radar` 目录。新电脑只需要安装 Git 与 Node.js 22.13 或更高版本，然后执行：

```powershell
git clone https://github.com/lightlink029-max/dongcheng.git
Set-Location dongcheng\outputs\lightlink-product-radar
npm ci
.\start-radar.cmd
```

源代码会同步，`.dev.vars`、本地 D1 数据库、导入文件、截图和日志不会上传。需要迁移业务数据时，先在旧电脑停止软件，再单独复制 `.wrangler/state`；不要把它提交到 Git。可选连接配置可参考 `.dev.vars.example`，每台电脑应生成自己的凭证库主密钥。

## 已完成的功能

- 情报总览：按目标地区、触发事件、画像和产品家族建立监控；支持搜索、筛选、分页、暂停、恢复与归档。
- 监控执行闭环：可立即执行单条监控或批量执行到期监控；本机调度器每 5 分钟检查一次到期任务，运行结果明确区分完成、等待数据和失败。
- 官方贸易自动采集：监控可维护 2/4/6/8 位 HS/CN 编码并选择 UN Comtrade、Eurostat Comext 和 UK HMRC；正式运行保存覆盖国家、配额说明、耗时、重试次数、最近成功和结构化失败原因。
- 来源健康与重试：网络、限流和远端服务错误最多自动重试一次；权限、范围和响应结构错误不会反复请求；无数据、确认零和失败分别记录。
- 统一信号入库：授权导出、官方数据、事件日历和本地贸易缓存使用同一去重指纹；同一事实跨监控复用，内容变化追加版本而不重复计数。
- 机会初筛：只有至少两个独立可靠来源、两类交叉证据，且包含贸易、采购或内部经营证据时才生成待人工复核候选；事件和注意力信号不能单独过闸。
- 事件日历与人工复核：记录事件窗口、采购提前期、交付截止和原始来源；候选支持接受、继续观察或填写原因后 Pass，接受也不会自动建立验证项目。
- 通用灰度测试台：每条监控可模拟候选达标、只有热度、等待数据和来源失败四条路径；使用正式证据闸门，但不污染正式信号、评分、候选或验证项目。
- 稳定来源目录：TikTok、Meta Ads、Instagram 与各跨境电商平台的配置入口独立于采集记录，即使清空业务数据也不会消失。
- 统一数据源中心：贸易、B2B、注意力和内部业务来源只维护一份连接目录和状态，其他页面仅引用，不再分别配置。
- 七层信号模型：事件、注意力、B2B 需求、供应与竞争、官方贸易、法规及内部经营数据分层保存，不混用口径。
- 采购触发目录：覆盖日常补货、返校季、换季、节庆、体育赛事、展会、战争与制裁、汇率与运价、极端天气、法规、设备更新、供应中断、招标、RFQ、社媒爆款与搜索增长。
- 来源边界：接入目录包括 UN Comtrade、Eurostat、HMRC、USITC/Census、加拿大统计局、日本海关、澳大利亚统计局、中国海关、Alibaba.com、中国制造网和 Global Sources，并明确“信号”与“成交事实”的区别。
- 验证项目闭环：项目从全球画像建立，可关联多个产品矩阵；候选家族上限可配置，默认 5 个；每轮用真实证据决定继续、调整、补充或 Pass。
- 证据复用：产品家族共享证据、项目引用和轮次结论分开保存，避免多项目重复调研；来源变化或证据过期时重新核验。
- 供应验证：产品家族与具体规格/产地/工厂/价格/MOQ/质量/交期分层记录，供应商能力只由报价、样品、验厂或履约事实形成。
- 生命周期：项目与轮次支持筛选、分页和作废；作废采用软归档，保留证据链和可审计历史。
- 关键词扫描：支持换行或逗号输入多个种子词，自动规范化并生成采购型变体。
- 热点发现任务：按类目建立真实数据采集任务；当前由 AI 协助采集或文件导入，不生成虚假热词。
- 增量导入：支持 CSV、TSV、JSON，同一任务分批导入不同平台时保留已有证据。
- 数据状态：严格区分有效值、确认 0、认证失败、限流、采集失败、不支持和地区不可用。
- 固定评分 v1.2：热度、实际增长动量、商业验证、采购意图、竞争度、机会和置信度可重复计算。
- 机会工作台：排序、状态筛选、详情证据、来源覆盖、CSV 导出。
- 第二阶段管理：历史快照、观察清单、建议复查日期、词簇合并与变体拆分。
- AI 页面工具：支持读取雷达、建立任务、写入证据和管理关键词状态；浏览器不支持 WebMCP 时，所有可见操作仍正常使用。
- Codex 多通道：关键词雷达、整项目调研、单产品辅助和图片采集分别进入独立的 Codex 任务；不同通道可并行，同一通道串行。`$lightlink-radar-bridge` 通过受限本地接口读取任务、写回证据并核对历史，不需要复制粘贴，也不需要在网页填写 OpenAI API Key。
- 任务与历史：执行进度和历史记录合并在一个页面；执行时展示建立、采集整理、写回雷达、复读确认四个阶段，完成后可按任务下载 CSV。
- API 配置中心：提供核心来源、主流海外电商平台与 OpenAI 的官方注册/文档入口，区分“公开页免密钥抽样”和“官方 API 需授权”，只显示是否配置，不回传密钥。
- AI 整理入库：可选择 10、15 或 20 个目标关键词簇；网页调用 OpenAI Responses API 扩词、检索公开证据并生成严格结构化观测，任务类型仍保留为“关键词扫描”或“热点发现”。
- 在线结果明细：一行展示中文品名、原关键词、多张图片、采购价、评分和来源；图片可切换、放大并打开原商品页，全球任务显示证据实际国家，跨产品重复图会自动隐藏。

## 导入规则

工作台内可下载 `import-template.csv`。每行代表一个“词簇 × 平台 × 指标”的观测，同一组合在一次导入中只能出现一次。可选字段 `keywordZh`、`imageUrls`、`imageSourceRef` 和采购价字段用于在线明细；图片必须是可公开访问的 HTTP(S) 直链，并能追溯到同一行记录的商品页或 API。

| 字段 | 说明 |
| --- | --- |
| `keyword` | 观测关键词 |
| `keywordZh` | 简体中文品名；用于在线明细管理，可留空 |
| `imageUrls` | 1–6 个对应产品的公开 HTTP(S) 图片直链，用 `|` 分隔；可留空 |
| `imageSourceRef` | 包含这些图片的原商品页或 API URL；有 `imageUrls` 时必填 |
| `imageUrl` | 旧版单图字段，仅用于兼容历史导入 |
| `purchasePriceMin` / `purchasePriceMax` | 同一可核验来源中的采购价范围；无证据时两项都留空 |
| `purchasePriceCurrency` / `purchasePriceUnit` | 三位币种代码（如 `USD`）与计价单位（如 `件`） |
| `platform` | 数据源页列出的核心来源或补充电商平台名称 |
| `metric` | `attention`、`commercial` 或 `competition` |
| `currentValue` | 当前真实值；失败状态必须留空 |
| `previousValue` | 同口径前期值；可留空 |
| `coverageDays` | 必须与任务窗口一致：7、30 或 90 |
| `sourceKind` | `official_api`、`official_export`、`browser_sample`、`open_source`、`manual_import` 或 `assistant` |
| `geoScope` | 与任务市场一致，例如 `US`；全球数据可用 `GLOBAL` |
| `status` | `ok`、`confirmed_zero`、`unsupported`、`auth_failed`、`rate_limited`、`collection_error`、`geo_unavailable` |
| `missingReason` | 失败或不可用状态必填 |
| `collectedAt` | ISO 时间，例如 `2026-09-15T08:00:00.000Z` |

状态和值的约束：

- `ok` 必须有非负 `currentValue`。
- `confirmed_zero` 的 `currentValue` 必须严格为 `0`。
- 失败或不可用状态的 `currentValue` 必须留空，并填写 `missingReason`。
- 空值不是 0；证据不足时机会分显示“待补证据”。

## 如何让我协助

使用 `start-radar.cmd` 启动软件后，点击工作台的“AI 整理并入库”，再点击“直接发送到 Codex”。关键词任务会进入“LightLink Radar 关键词雷达”；项目、单产品和图片任务分别进入各自的 Codex 通道，可同时处理。无需复制、粘贴或在网页填写 OpenAI API Key，结果会自动写回机会榜、调研项目、来源明细和历史记录。

发送后可点击页面顶部的“任务执行中”或左侧“任务与历史”查看阶段和写回情况。页面每 4 秒自动更新；“已写回 · 部分来源可用”表示任务已经结束，只是仍有平台证据缺失，并非仍在执行。每条已写回记录右侧都有“下载 CSV”，导出该任务的关键词、变体、评分和证据统计。

也可以在工作台建立任务后，直接告诉 Codex：

> 为当前雷达任务采集核心来源，并选择与目标市场最相关的海外电商平台补充商品、图片和采购价证据；记录链接、时间、国家、样本量与失败状态，然后增量写回并解释评分。

采集需要遵守平台登录权限、接口政策和频率限制。认证失败、权限失败或限流不会自动绕过或无限重试。当前版本没有内置平台账号；后台调度只复用本地缓存和事件记录，并为未授权来源建立“等待授权/导入”的运行记录，不会伪装成外部采集成功。

本机 Skill 位于 `C:\Users\Admin\.codex\skills\lightlink-radar-bridge`。项目内的受限桥接脚本可用于检查连接：

```powershell
node scripts/codex-radar-bridge.mjs status
```

自动通道只监听 `127.0.0.1:8788`，只接受来自本机雷达页面的结构化任务字段，不提供任意命令接口。它通过 Codex App Server 创建或复用一个专用任务；不会向正在运行的任意对话注入文字，也不嵌入 `chatgpt.com` 网页。

## API 配置（免费优先）

点击页面右上角“API 配置”，可查看各数据源的官方注册入口、权限说明、费用属性和所需变量。优先顺序建议为：官方免费额度或官方导出、公开来源、AI 整理；不默认购买第三方数据。

长期配置时，在页面下载模板并保存为项目根目录的 `.dev.vars`，只填写需要使用的平台，然后重新启动 `start-radar.cmd`。该文件已被 Git 忽略。网页和数据库只显示是否检测到配置，不显示或保存密钥内容。

OpenAI 也支持在页面临时填写 API Key；它只保留在当前页面内存并随单次请求发送，刷新页面后清除。OpenAI API 通常按量计费，只有主动点击“AI 整理”时才会调用。所有来源的自动采集仍需按平台权限逐项实现；配置凭证或公开商品结果都不代表已获得全站关键词搜索量。

## 数据位置与备份

数据保存在项目内的 `.wrangler/state` 本地 D1 状态目录。备份时先停止软件，再复制整个 `.wrangler/state` 文件夹。项目不会写入 Odoo；如以后需要同步到 Odoo，仍须单独预览、确认并验证写入。

## 后续在线查看

可以。当前技术栈已经按 Cloudflare Sites + D1 兼容方式构建，后续可将同一工作台发布成私有网址，并把本地数据迁移到在线 D1。建议上线时启用登录访问，避免公开关键词、供应情报和来源链接。

在线化尚未执行，也没有产生公网地址。上线阶段主要增加：

1. 私有登录和用户隔离；
2. 生产 D1 迁移与本地数据导入；
3. 可信平台连接器、密钥管理和采集审计；
4. 生产级计划任务、失败告警和仅在显著变化时通知。

## 技术说明

- UI：React、Tailwind、Recharts
- 运行时：Vinext / Cloudflare Worker
- 数据：Drizzle + D1；本地由 Miniflare 持久化
- 数据表：扫描任务、关键词簇、原始观测、评分快照、观察清单、个人设置
- 评分与安全测试：Node 内置测试；CSV 导出包含公式注入防护

本版本的数值均为同批、同市场、同窗口下的相对或规则评分，不等同于平台官方搜索量，也不代替毛利、认证、物流、MOQ 与供应稳定性验证。
